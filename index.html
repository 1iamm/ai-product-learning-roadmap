6-WEEK LEARNING ROADMAP

AI 时代产品全栈思维
学习路线

面向有 Java / 后端工程背景、开始参与前端、小程序、SaaS、AI Agent 和产品工作的工程师。目标不是转成传统 PM，而是建立从用户问题到产品决策、体验设计、数据验证和系统实现的完整思维链。

Growth.Design · UX / 用户行为SVPG · 产品判断 / DiscoveryMixpanel · Product Analytics每周必须有实战产出
HOW TO USE THIS ROADMAP

每个阶段都固定回答 4 个问题

1. 学什么

明确这一阶段要建立的概念和判断框架。

2. 去哪里学

直接给 Growth.Design、SVPG、Mixpanel 的学习资料链接。

3. 怎么验证

必须通过实战产出或陌生产品分析来验收，而不是看阅读量。

4. 学完得到什么

明确这一阶段对你实际工作判断能力的提升。

CORE LOOP

这 6 周真正要练的闭环

User Need → Journey → Friction → Product Decision → Outcome → Metric → Experiment → Iteration

不是记概念，而是把任何陌生产品都能沿着这条链拆开。

WEEK 1 · USER

先学会看用户，而不是看功能

关键词：User Need · JTBD · User Journey · Friction

01
① 这一阶段要学习什么
  • 理解 User Need、JTBD、User Journey、Friction 的区别。
  • 学会从“用户要完成什么任务”而不是“系统有哪些功能”看产品。
  • 识别主路径、关键节点、认知负担和不必要步骤。
② 学习资料
  • Growth.Design：Headspace — Jobs-to-be-Done ↗
  • Growth.Design：McDonald’s Self-Serve UX ↗
  • Growth.Design：Blinkist Onboarding ↗
③ 学完怎么验证
  • 随机选一个常用 App，15 分钟内画出核心 User Journey。
  • 至少指出 3 个 Friction，并说明它为什么会影响用户。
  • 能解释 JTBD 和“用户需求列表”的区别。
④ 学完会收获什么
  • 从“功能视角”切换到“用户任务视角”。
  • 看到页面时会主动问：用户为什么来、下一步是什么、哪里会卡住。
  • 以后做前端、小程序或 SaaS 时，不再直接从页面或接口开始设计。
WEEK 2 · VALUE

找到 Activation 和 Time to Value

关键词：Onboarding · Aha Moment · Activation · Time to Value

02
① 这一阶段要学习什么
  • 理解 Onboarding、Activation、Aha Moment、Time to Value。
  • 判断“注册成功”和“真正获得价值”为什么不是一回事。
  • 学习如何减少用户从进入产品到首次成功之间的步骤。
② 学习资料
  • Growth.Design：Adobe Free Trial UX ↗
  • Growth.Design：Trello User Onboarding ↗
  • Mixpanel：2026 Product Analytics Guide ↗
③ 学完怎么验证
  • 给 3 个产品分别定义一个候选 Activation Event，并解释原因。
  • 画一条 Time to Value 路径，至少删除或后置一个非必要步骤。
  • 能说明为什么“注册数上涨”不等于产品变好。
④ 学完会收获什么
  • 会开始用“用户什么时候第一次感受到价值”判断产品设计。
  • 能够优化新用户流程，而不是只关注注册和页面完成度。
  • 以后做 AI 产品时，会主动压缩用户到首次有效结果的时间。
WEEK 3 · PRODUCT

从 Feature Thinking 转向 Outcome Thinking

关键词：Problem · Outcome · Output · Discovery · Product Risk

03
① 这一阶段要学习什么
  • 理解 Problem vs Solution、Output vs Outcome、Discovery vs Delivery。
  • 学习产品风险：Value、Usability、Feasibility、Viability。
  • 学会先验证不确定性，再进入完整开发。
② 学习资料
  • SVPG：Product Model Concepts ↗
  • SVPG：最新文章与 Product Discovery 文章 ↗
  • SVPG：Product Discovery 主题集合 ↗
③ 学完怎么验证
  • 挑一个真实需求，写出 Problem / User / Outcome / Hypothesis / Risk / Validation。
  • 把“做某个功能”改写成可衡量的 Outcome。
  • 面对新需求时，能先提出至少 5 个产品问题，再谈技术实现。
④ 学完会收获什么
  • 从“需求执行者”转向“问题定义者”。
  • 会判断一个需求是在解决问题，还是只是预设了某个方案。
  • 减少做完功能才发现“没人用 / 没效果”的概率。
WEEK 4 · DATA

学会用 Funnel 和 Cohort 找问题

关键词：Event · Funnel · Conversion · Cohort · Segmentation

04
① 这一阶段要学习什么
  • 理解 Event、Property、Funnel、Conversion、Cohort、Segmentation。
  • 学习如何把用户旅程转成可观测的行为事件。
  • 理解“发现掉点”和“解释掉点原因”是两件事。
② 学习资料
  • Mixpanel：2026 Product Analytics Guide ↗
  • Mixpanel：What is Product Analytics? ↗
  • Mixpanel：Product Analytics Examples ↗
③ 学完怎么验证
  • 为一个真实产品定义 6–10 个核心 Event 和必要 Property。
  • 设计一条核心 Funnel，并解释每一步的业务含义。
  • 看到一个漏斗掉点时，提出至少 3 个需要进一步验证的假设。
④ 学完会收获什么
  • 会把“用户感觉不好用”转化成可以观测和验证的问题。
  • 产品上线后不再只看 GMV、PV、UV，而会看关键行为链路。
  • 开始具备用数据定位产品问题的能力。
WEEK 5 · RETENTION

从一次转化，进入生命周期和增长

关键词：Retention · Churn · Trigger · Lifecycle · Growth Loop

05
① 这一阶段要学习什么
  • 理解 Retention、Churn、Lifecycle、Trigger、Growth Loop。
  • 学习“什么时候触达”与“触达什么”之间的关系。
  • 区分一次性促销、运营动作和可持续增长机制。
② 学习资料
  • Growth.Design：LinkedIn Retention Triggers ↗
  • Growth.Design：Loom Growth ↗
  • Growth.Design：Spotify Wrapped ↗
  • Growth.Design：Typeform Offboarding ↗
③ 学完怎么验证
  • 画出 New → Activated → Active → At Risk → Churned → Resurrected 生命周期。
  • 设计 3 个基于用户行为触发的运营策略，并写目标指标。
  • 画出一个真正可循环的 Growth Loop，而不是普通漏斗。
④ 学完会收获什么
  • 从“做活动”升级到“经营用户生命周期”。
  • 会把运营动作和用户状态、产品行为、数据指标连接起来。
  • 开始理解增长不是一次性拉新，而是系统性机制。
WEEK 6 · CAPSTONE

把产品、UX、数据、运营和系统串起来

关键词：Product System · Experiment · State · AI Native

06
① 这一阶段要学习什么
  • 把前 5 周知识整合成一个 Product System。
  • 把 User、UX、Data、Growth、Domain、State、AI 边界放进同一张图里。
  • 学习从一个模糊业务问题形成完整产品方案。
② 学习资料
  • Growth.Design：任选 1 个相似产品案例复盘 ↗
  • SVPG：复查 Product Discovery / Outcome ↗
  • Mixpanel：复查 Activation / Funnel / Retention ↗
③ 学完怎么验证
  • 完成一份不超过 8 页的 Product System Case Study。
  • 让另一个人只看你的文档，就能说清产品目标、路径、指标和最大风险。
  • 随机拿一个陌生产品，15 分钟完成完整拆解。
④ 学完会收获什么
  • 从“只会后端实现”进入产品、运营、数据、系统综合思考。
  • 能把模糊业务问题整理成可讨论、可验证、可开发的方案。
  • AI 可以帮助你执行，但你开始具备决定“应该做什么”的能力。
WEEKLY REVIEW

每周只记录这 5 件事

  1. 本周我真正改变了哪个认知？
  2. 我现在会问哪些以前不会问的问题？
  3. 哪个概念我只是“听懂了”，但还不会用？
  4. 我在哪个真实项目上用了一次？
  5. 下周只补哪个最明显的短板？
NOTES

本周复盘

SUCCESS CRITERIA

学完 6 周后，不看“读了多少篇”，看你是否发生这 4 个变化

01
从实现需求 → 质疑需求

先问 Problem、User、Outcome、Risk，再谈技术。

02
从页面视角 → 用户旅程视角

能识别 Friction、Time to Value、Activation，而不仅是 UI 好不好看。

03
从上线完成 → 数据验证

知道 Event、Funnel、Cohort、Retention 怎么帮助验证假设。

04
从单功能 → 产品系统

能把用户、运营、指标、状态、系统和 Agent 串成一套闭环。
